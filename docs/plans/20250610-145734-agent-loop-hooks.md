## Chapter 2: Detailed Technical Plan

### 2.1 Design Overview

AgentLoop 的 `run(userMessage)` 方法是一个 `while(true)` 循环，负责与 model 交互和 tool 执行。Hook 机制在不改变原有控制流的前提下，在 5 个关键节点插入可扩展的拦截点：

```
run(userMessage)
  ├─ UserPromptSubmit → 可短路直接返回 result
  ├─ [system prompt + user message 组装]
  ├─ while(true):
  │   ├─ model.invoke()
  │   ├─ if tool_calls:
  │   │   ├─ 对每个 toolCall:
  │   │   │   ├─ PreToolUse → 可跳过原始 tool 执行
  │   │   │   ├─ tool.execute() / 或 hook 提供的 result
  │   │   │   ├─ PostToolUse（成功时）
  │   │   │   └─ PostToolUseFailure（失败时）→ 可修复错误
  │   │   └─ continue
  │   └─ else: break
  └─ Stop → 可覆盖最终返回值
```

**核心测试 case**：
1. `UserPromptSubmit` 返回 result 时，`run()` 直接返回该 result，不调用 model（短路测试）
2. `PreToolUse` 返回 result 时，跳过 `tool.execute()`，将该 result 作为 tool 结果写入 messages（拦截测试）
3. 注册 2 个同类型 hook，第一个返回 result A，第二个返回 result B，最终取 B（链式覆盖测试）
4. `PostToolUseFailure` 返回 result 时，错误被修复，result 作为成功结果继续（修复测试）
5. Hook 抛错时，`run()` 直接 reject，不吞异常（fail-fast 测试）

### 2.3 Interface / API Design

```ts
// src/agent-loop.ts

export interface UserPromptSubmitContext {
  userMessage: string;
  systemPrompt?: string;
  messages: ChatMessage[];
}

export interface PreToolUseContext {
  userMessage: string;
  toolName: string;
  args: Record<string, unknown>;
  toolCallId: string;
  messages: ChatMessage[];
}

export interface PostToolUseContext {
  userMessage: string;
  toolName: string;
  args: Record<string, unknown>;
  result: string;
  toolCallId: string;
  messages: ChatMessage[];
}

export interface PostToolUseFailureContext {
  userMessage: string;
  toolName: string;
  args: Record<string, unknown>;
  error: Error;
  toolCallId: string;
  messages: ChatMessage[];
}

export interface StopContext {
  userMessage: string;
  result: string;
  messages: ChatMessage[];
}

export interface HookResult<TContext> {
  context: TContext;
  result?: string;
}

export interface AgentLoopHooks {
  userPromptSubmit?(
    ctx: UserPromptSubmitContext,
  ): Promise<HookResult<UserPromptSubmitContext>>;
  preToolUse?(
    ctx: PreToolUseContext,
  ): Promise<HookResult<PreToolUseContext>>;
  postToolUse?(
    ctx: PostToolUseContext,
  ): Promise<HookResult<PostToolUseContext>>;
  postToolUseFailure?(
    ctx: PostToolUseFailureContext,
  ): Promise<HookResult<PostToolUseFailureContext>>;
  stop?(
    ctx: StopContext,
  ): Promise<HookResult<StopContext>>;
}

export interface AgentLoopConfig {
  model: Model;
  systemPrompt?: string;
  tools?: Tool<z.ZodSchema>[];
  hooks?: AgentLoopHooks[];
}
```

**接口测试 case**：
1. `AgentLoopHooks` 的所有方法都是可选的，用户只需实现需要的 hook
2. `AgentLoopConfig` 传入 `hooks` 数组后，各 hook 方法按预期触发
3. 各 Context 类型字段与预期一致，hook 可以修改 `messages` 数组（引用透传）

### 2.4 Implementation Steps

- [ ] **Step 1**: 在 `src/agent-loop.ts` 中定义所有 hook 相关类型（Context、HookResult、AgentLoopHooks）
- [ ] **Step 2**: 实现 hook 执行辅助函数 `executeHooks<T>(hooks, method, context) => Promise<{ context, result? }>`，负责串行调用多个 hook 实例的同名方法，透传 context，取最后一个非 undefined 的 result
  - 测试 case: 空 hooks 数组直接返回原 context / 单个 hook 修改 context 并返回 result / 多个 hook 链式覆盖 result
- [ ] **Step 3**: 在 `AgentLoop` 构造函数中接收 `config.hooks`
- [ ] **Step 4**: 在 `run()` 方法中插入 5 个 hook 调用点
  - `UserPromptSubmit`：组装 messages 之前，如返回 result 直接 return
  - `PreToolUse`：找到 tool 后、`execute()` 之前，如返回 result 跳过 execute
  - `PostToolUse`：execute() 成功后
  - `PostToolUseFailure`：execute() catch 块中，如返回 result 则当作成功处理
  - `Stop`：return 之前，如返回 result 则覆盖返回值
  - 测试 case: 每个点位独立验证触发时机和短路/覆盖行为
- [ ] **Step 5**: 更新 `src/index.ts` 导出新类型
- [ ] **Step 6**: 运行 `pnpm run test` 确保全部通过
- [ ] **Step 7**: 运行 `pnpm run lint` 和 `pnpm run format`

### 2.6 Risks & Mitigations

| 风险 | 影响 | 缓解措施 | 回归测试 |
|------|------|----------|----------|
| Hook 修改 messages 引用导致循环状态混乱 | 中 | messages 作为引用透传是设计意图，但 MVP 阶段保持简单；后续如需不可变可引入深拷贝 | Context messages 可修改测试 case |
| Hook 抛错导致整个 run() 失败 | 低 | fail-fast 是设计意图，用户应在 hook 内部自行处理可恢复错误 | Hook 抛错 fail-fast 测试 case |
| 现有测试因 run() 内部重构而失败 | 低 | 保持原有控制流不变，仅在关键节点插入 hook 调用；所有现有测试应继续通过 | 运行全部现有测试验证 |
